# ha-barrier-auto-open — авто-открытие шлагбаумов по детекции машин

Стек для Home Assistant: локальное распознавание машин на камерах
А.М.Видео и ЕГДС (облачные шлагбаумы) и автоматическое открытие шлагбаума.
Работает **на CPU, без GPU**.

```
А.М.Видео (облако, WSS/MPEG-TS)──┐
                                 │  bridge  ──H.264──▶  mediamtx ──RTSP──▶  Frigate (детекция car)
ЕГДС (облако, HTTPS-снимки)──────┘  (docker)            (RTSP)       │  MQTT
                                                                      ▼
                                                        Home Assistant
                                                        - уведомление с фото + кнопка «Открыть»
                                                        - авто-открытие (машина + телефон в пути)
```

Компоненты (все в `docker-compose.yml`):

| Сервис | Образ | Роль |
|---|---|---|
| `bridge` | `./bridge` (python:3.12-slim + ffmpeg) | мостик: облачные камеры → H.264 → RTSP |
| `mediamtx` | bluenviron/mediamtx | локальный RTSP-сервер |
| `frigate` | ghcr.io/blakeblackshear/frigate:0.18.2 | детекция машин (CPU-детектор) |
| `mosquitto` | eclipse-mosquitto:2 | MQTT-брокер (события Frigate → HA) |

Протоколы облачных сервисов восстановлены при разработке HACS-интеграций
[amvideo-ha](https://github.com/NoIDXMV6/amvideo-ha) и
[egds-ha](https://github.com/NoIDXMV6/egds-ha); карточки для панелей —
в [ha-barrier-cards](https://github.com/NoIDXMV6/ha-barrier-cards).

## Требования

- Любая машина с Docker и docker compose (достаточно VM, где стоит HAOS —
  стек ставится рядом) и доступом в интернет.
- CPU с инструкциями AVX/AVX2, ~4 ГБ RAM свободной. GPU/Coral не нужны:
  детектор CPU + кодирование x264 veryfast справляются с 2 камерами.
- Свободные порты: 5000 (Frigate UI), 1883 (MQTT), 8554 (внутри compose).
- Диск под контейнеры + логи (запись архива по умолчанию выключена).

## Установка

### Шаг 1. Скопировать стек на машину с Docker

```bash
git clone https://github.com/NoIDXMV6/ha-barrier-auto-open.git
cd ha-barrier-auto-open
cp bridge/config.example.yaml bridge/config.yaml
```

### Шаг 2. Заполнить `bridge/config.yaml`

**А.М.Видео** — телефон и пароль от приложения (`id_shlag` — атрибут
«ID shlag» у камеры в HA, например 2026).

**ЕГДС** — нужны учётные данные именно КАМЕРЫ (логин/пароль rsapi).
Они получаются один раз помощником (на любой машине с python3):

```bash
pip install aiohttp cryptography
python bridge/get_egds_camera_creds.py 79001234567
# → придёт SMS с кодом, введите его — скрипт напечатает готовый YAML-блок
```

Вставьте напечатанный блок в `bridge/config.yaml` (host/port/guid уже
будут заполнены).

### Шаг 3. Запустить

```bash
docker compose up -d --build
docker compose logs -f bridge      # убедиться, что оба источника «подключение к …»
```

Проверка потоков (VLC/ffprobe): `rtsp://<IP-машины>:8554/govorovo` и
`/lesnaia` (порт 8554 наружу по умолчанию закрыт — раскомментируйте
`ports` у mediamtx в compose для проверки, потом закройте обратно).
Веб-интерфейс Frigate: `http://<IP-машины>:5000` — должны появиться
камеры и детекции «car».

### Шаг 4. Подключить Home Assistant

1. **MQTT**: Настройки → Устройства и службы → Добавить интеграцию →
   **MQTT** → брокер `<IP-машины>`, порт `1883` (без пароля — broker
   анонимный, при желании ограничьте сетью дома).
2. **Frigate**: HACS → Integrations → **Frigate** → URL
   `http://<IP-машины>:5000`.
3. **Автоматизации** (папка `automations/`): вставьте содержимое через
   Настройки → Автоматизации → Создать → ⋮ → «Изменить в YAML»:
   - `notify_car_detected.yaml` — фото с кнопками «Открыть»/«Игнор»;
   - `open_from_notification.yaml` — обработка кнопки;
   - `auto_open_by_geo.yaml` — авто-открытие (машина + ваш телефон в пути).
   Подставьте свои: `notify.mobile_app_ТЕЛЕФОН`, `device_tracker.ТЕЛЕФОН`,
   IP Frigate и ID кнопок (Инструменты разработчика → Состояния,
   фильтр `otkryt`).

## Логика открытия (без распознавания номеров)

Номера на ваших камерах не читаются, поэтому «свою» машину определяем
надёжными способами:

1. **Фото + кнопка** (базовый режим): Frigate видит машину → телефон
   получает снимок и кнопку «Открыть». Нажали — шлагбаум открылся.
   Чужим не откроется никогда.
2. **Авто-открытие по совпадению**: Frigate видит машину **И** ваш
   телефон вне дома (едете) → открыть автоматически. Курьеры и соседи
   не откроют.
3. **Опционально, следующим этапом**: фильтр по признакам машины
   (цвет/тип через локальную VLM-модель Ollama, например qwen2.5-VL)
   — снимику у шлагбаума задается вопрос «какая это машина», ответ
   сверяется с белым списком. Требует отдельной машины с Ollama или
   свободных ресурсов; добавим по запросу.

## Важные особенности

- **А.М.Видео держит одну активную сессию на аккаунт.** Мостик и
  HA-интеграция будут периодически «пере логиниваться» друг у друга —
  возможны короткие перерывы камеры в HA. Рекомендуется камеры А.М.Видео
  смотреть во Frigate (HACS-интеграция Frigate создаёт сущности
  `camera.govorovo`), а камеру интеграции amvideo в HA отключить
  (сущность → переключатель «Включено» → выкл). ЕГДС этого не касается.
- **ЕГДС** отдаёт снимки (~2 кадр/с) — потока как у А.М.Видео нет,
  для детекции машин этого достаточно, задержка детекции до ~2–3 с.
- **Защита от дребезга**: повторное открытие ограничено ~20 с
  (штатно в обеих интеграциях) — автоматизация не сможет «заштормить»
  шлагбаум.
- **Зоны Frigate**: чтобы детекция срабатывала только у шлагбаума
  (а не на дороге в кадре), нарисуйте зону в Settings → Cameras →
  Zones и добавьте её в `objects.filters.car.zones` конфига.
- Первый старт Frigate скачивает детекционную модель из интернета,
  дальше всё работает офлайн.

## Структура

```
ha-barrier-auto-open/
├── docker-compose.yml          # весь стек (4 контейнера)
├── mosquitto/mosquitto.conf
├── frigate/config.yml          # детекция car, CPU, 2 камеры
├── bridge/
│   ├── main.py                 # мостик (amvideo: WSS→x264; egds: снимки→x264)
│   ├── get_egds_camera_creds.py# одноразовый helper учётных данных ЕГДС
│   ├── config.example.yaml
│   ├── Dockerfile
│   └── requirements.txt
└── automations/
    ├── notify_car_detected.yaml
    ├── open_from_notification.yaml
    └── auto_open_by_geo.yaml
```

## Отладка

```bash
docker compose logs -f bridge      # мостик: вход, подключение, ошибки снимков
docker compose logs -f frigate     # детекция, ошибки RTSP
docker compose restart bridge      # перезапуск мостика
```

Если `lesnaia` пишет `401` — неверные учётные данные камеры ЕГДС:
пароль должен быть **расшифрованным** (повторите helper-скрипт).
Если `govorovo` пишет «сервер не выдал порт» — камера занята другой
сессией А.М.Видео (мобильное приложение/интеграция), повторится сам.
